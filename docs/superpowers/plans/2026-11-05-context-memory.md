# 游戏上下文整理实施计划

**目标：** 放宽旧85KB裁剪，约50万输入token自动整理记忆；整理时冻结游戏、持续显示气泡，成功后恢复。

**架构：** 沿用DSH“旧历史摘要＋完整近期消息”的思路，不引入DSH会话运行时。独立memory模块负责估量与拆分，Agent负责一次摘要请求和持久化，Runtime负责可取消的冻结/恢复。使用API实报token校准估量，未测量时使用文本UTF-8字节保守上界，图片单独预留；界面明确估计值。

**约束：** 不新增依赖、模型工具或后台进程；不修改DSH全局配置；原世界保持暂停。摘要调用计入余额与用量，失败不丢历史，不自动重试扣费。仅对本项目直接API循环生效。

**文件：** src/memory.mjs、src/agent.mjs、src/runtime.mjs、src/state.mjs；原生FishHud和web/overlay.mjs；tests/memory.test.mjs与当前README/架构/使用说明。

**重点检查：** 工具调用与响应不可拆散；重开后保留摘要和计量；人工暂停/断线不可自动恢复；空摘要或超时不覆盖历史；整理期间时钟与世界冻结。

- [x] Runtime冻结、停止计时；成功且生命周期未变才恢复。原生/网页气泡优先显示“正在压缩上下文”。
